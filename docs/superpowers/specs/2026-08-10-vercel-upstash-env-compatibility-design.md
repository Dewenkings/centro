# Vercel Upstash Environment Compatibility

## Goal

Allow the public-demo quota service to use either the canonical Upstash REST environment variables or the names generated by the connected Vercel Storage integration, without exposing or duplicating credentials.

## Design

The quota configuration resolver will select credentials in this order:

1. `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.
2. `UPSTASH_REDIS_REST_KV_REST_API_URL` and `UPSTASH_REDIS_REST_KV_REST_API_TOKEN`.

Credentials must come from a complete pair. The resolver will not mix a URL from one naming convention with a token from another. If neither complete pair exists, quota checks remain fail-closed with `QUOTA_UNAVAILABLE`.

## Compatibility and Security

- Existing deployments using canonical Upstash variables keep precedence and behavior.
- Vercel-managed secrets remain server-only and do not need to be copied into manually created variables.
- No credential values are logged, returned to the browser, or committed.
- Quota limits, Redis key format, reset timing, and HTTP responses remain unchanged.

## Verification

- Add a test proving the Vercel-generated pair can execute a quota check.
- Add a precedence test proving the canonical pair wins when both pairs exist.
- Run the focused quota tests, full test suite, and production build before committing.
